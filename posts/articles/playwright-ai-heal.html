Playwright AI Heal

Apr 10, 2026 #Playwright #TypeScript #AI #Testing 6 min

Intro

I am wary of leaning on LLMs for every test fix: auto-healing is tempting, but if each flaky locator means a slow model round trip, suites only get heavier.

I still wanted to try the pattern. marttinm/playwright-auto-healer is a solid LLM-first take; it worked well enough that I built playwright-ai-heal with a different order of operations: local DOM resolver and cached heals first, then optional remote providers (Groq, Ollama, Anthropic, Gemini—see .env.example).

What it does

When locator.click or locator.fill fails, the library can retry with a better selector. Healing is layered: reuse what already worked, run heuristics on the live page, then call an LLM if needed. Opt in by importing test (and expect) from playwright-ai-heal instead of @playwright/test so the page fixture can instrument locators. Today only click and fill are wired; other actions would be natural extensions.

Quick start

  1. Install dependencies (peer: @playwright/test ≥ 1.40) and browsers: 
    
                  npm install
                  npx playwright install
  2. Import from this package: 
    
                  import { test, expect } from 'playwright-ai-heal';
  3. Copy .env.example to .env and set keys if you use a remote provider; local-only paths work with defaults.
  4. Run tests as usual—no custom CLI: 
    
                  npx playwright test

Environment toggles

See the repo README for the full table; these are the switches I use most:

  • USE_AI_HEAL — set to false / 0 / off to disable instrumentation for a baseline run.
  • USE_LOCAL_RESOLVER — when true, run the rule-based resolver on the DOM before any LLM call (saves latency and cost when it finds a unique match).
  • PREFER_HEALED_LOCATOR — when true, try persisted or in-session healed selectors before the original locator on each action.
  • AI_PROVIDER — ollama, gemini, anthropic, or groq; can be inferred from API keys when unset.

How healing is ordered

On locator.fill / locator.click failure (and optionally before the original when prefer-healed is on):

  1. Persisted mappings in .playwright-healer/recommendations/selector-recommendations.json (from the last report refresh).
  2. In-memory session cache for the current Node process.
  3. AutoHealer.healSelector: local DOM resolver (if enabled), then an LLM suggestion, then validation with waitFor on the page.

Artifacts land under .playwright-healer/ (temp logs plus merged recommendations). The sample config can run writeHealingReport() from globalTeardown so selector-recommendations.json and a markdown summary stay in sync after npx playwright test.

What’s next

  • Extend healing beyond click / fill (e.g. checks, drag, file inputs).
  • CI or PR hooks that surface selector drift from saved recommendations, not only at test time.

For day-to-day use, the point is to keep most recoveries cheap and local, and treat the LLM as a fallback—not the default path for every action.
