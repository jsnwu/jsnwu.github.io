Playwright Locator Auto Heal (Local and AI)

Apr 10, 2026 #Playwright #TypeScript #AI #Testing 6 min

Intro

I am skeptical about leaning on LLMs for test maintenance. Auto-healing sounds convenient, but if every flaky locator triggers a slow round trip to a model, end-to-end suites only get heavier.

The idea still stuck with me after chats at work and posts I read online. Finally, I come across a github project marttinm/playwright-auto-healer—solid LLM-driven healing—and the results were encouraging.

I used that as a starting point and created playwright-ai-heal with a few changes I wanted: a local DOM resolver first (fast, no tokens), cached heals from earlier runs, and providers such as Groq when you do want a free remote model. It's a simple project to start with and will keep evolving until it meets my needs.

What it does

When a click or fill fails, the library can retry with a better selector. Healing is layered: reuse what already worked, run heuristics on the live page, then call an LLM if needed. You opt in by importing test from playwright-ai-heal instead of @playwright/test so the page fixture can instrument locators.

This project is a plug and play library that can be used in any existing Playwright project. The injection of the healing logic can be plugged in at the base test, or simiply replace the import of test poiting over to the heal folder as shown from the test file.

Currently it's only limited to click and fill actions and using locator() to get the element. It can be extended to other actions in the future.

Quick start

  1. Install dependencies (peer: @playwright/test ≥ 1.40) and browsers: 
    
                  npm install
                  npx playwright install
  2. Import from this package: 
    
                  import { test, expect } from 'playwright-ai-heal';
  3. Copy .env.example to .env and set keys if you use a remote provider; local-only paths work with defaults.
  4. Run tests as usual—no custom CLI: 
    
                  npx playwright test

Environment toggles

See the repo README for the full table; these are the switches I use most:

  • USE_AI_HEAL — set to false to disable instrumentation for a baseline run.
  • USE_LOCAL_RESOLVER — when true, run the rule-based resolver on the DOM before any LLM call (saves latency and cost when it finds a unique match).
  • PREFER_HEALED_LOCATOR — when true, try persisted or in-session healed selectors before the original locator on each action.
  • AI_PROVIDER — ollama, gemini, anthropic, or groq; can be inferred from API keys when unset.

How healing is ordered

On a user action failure (and optionally before the original when prefer-healed is on):

  1. Persisted mappings in .playwright-healer/recommendations/selector-recommendations.json (from the last report refresh).
  2. In-memory session cache for the current Node process.
  3. AutoHealer.healSelector: local DOM resolver (if enabled), then an LLM suggestion, then validation with waitFor on the page.

Artifacts land under .playwright-healer/ (temp logs plus merged recommendations).
